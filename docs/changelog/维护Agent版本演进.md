## 文档 v2.2（2026-11-07，实施于系统 v0.12.0）

落地"护栏过严致长任务中断"与"工具分级体系混乱"两项整改（含本次排查发现的两个 bug）：

- **护栏口径重构**：删除累计 token 预算（原 200k，随轮数近平方增长必然先触发且口径与计费脱节），改为**单任务成本上限**（默认 ¥2，`system_config.agent_task_cost_limit`，设置页可调）；轮数上限 24→40，距上限 5 轮起注入软提示（软着陆）；护栏均按单次任务计，叫停时模型输出三段式小结 + SSE 新增 `task_paused` 事件，前端输入框上方出现"继续任务"一键续跑；
- **两个 bug 修复**：① 压缩兜底按消息条数估算放大 9 倍导致永不触发（超窗后被上游 400 打断），改为沿 user 边界整轮折叠至窗口 60%；② 续轮请求零重试零切换（单渠道一次抖动即中断长任务），首轮与续轮统一 `_open_round`：复用渠道 + 同渠道重试一次 + 跨渠道 failover；
- **工具体系整改**：删除工具级 `always_confirm` 标记（实质是横切在等级之上的隐藏"L1.5"，三档行为与 L2 完全一致）——原强审 5 工具按行为等价并入等级：`create_channel` / `create_model` / `delete_skill` / `sandbox_exec` → **L2 关键写**，`save_skill` → **L1 可逆写**（行为变化：部分审批档下保存技能不再弹卡）；风险分布 14/3/6；弹卡行为收敛为"档位 × 等级"一张查表，无任何例外名单；
- **执行上限声明化**：原"L2 每会话 5 次"恒定上限改为按工具声明的 `session_limit`——删除类 10 次（每次真删前有人工审批卡，5 次撑不住批量清理场景）、沙箱 30 次（此前不占 L2 配额等于无限，data-governance 单次治理约 2–4 次调用，首次给显式上限）、create 类不限次；配额按 `agent_message.tool_name` 计数（成功口径），旧 L2 记录保守并入两个删除工具；
- **前端整改**：右栏下线"风险等级"图例卡片（内部分级编码不外露）；审批卡标签翻译为"写操作 / 高危操作"；帮助弹窗（提示 / 安全）与审批档位描述全部改为用户视角措辞；上下文水位卡移除阈值说明句；设置页新增"单任务成本上限"；
- 需手动 DDL：`agent_message` 加 `tool_name` 列。

## 文档 v1.4（2026-11-07 记录，问题均已修复）

> 原"现存问题"节，三项均于 v0.11.0 修复后归档至此。

### 17.1 缺少上下文窗口的可视化入口 ✅ 修复于 v0.11.0

- **现象**：前端没有展示当前会话驱动模型的上下文窗口上限（`context_length`），也没有"当前已占用多少上下文"的读数。上下文水位只在两级策略内部生效（超窗口 70% 触发压缩、隔轮工具结果脱水），管理员全程不可见。
- **影响**：无法预判"还能聊多久、什么时候会被压缩脱水"，长会话中只能从消息被折叠占位的蛛丝马迹里反向猜测；切换小窗口模型时上下文可能骤然被压缩，也没有提前感知。
- **修复**：右栏新增"上下文水位"卡片，进度条展示 已用 / 上限；已用口径为 `round_end` 新增的 `contextTokens`（最近一轮官方 prompt_tokens，比累计 usageSoFar 更准确——后者含已脱水历史，不代表当前上下文占用），切会话从历史最后一条 assistant 消息恢复；≥70% 橙 / ≥90% 红。

### 17.2 工具与 Skill 数量偏多，需要精简 ✅ 修复于 v0.11.0

- **现象**：36 个工具 + 6 个内置 Skill，对单一管理员的运维场景而言工具面偏大；部分工具使用频率低，或与既有管理页能力重叠。
- **影响**：每轮请求都携带全部工具的 JSON Schema 与 skill 目录，常驻 token 开销随数量线性上涨；工具越多，模型选择时的干扰面越大、误选率越高；每个工具的脱敏、审批、测试、文档维护成本也随之增加。
- **修复**：36 → 23——下线与合并明细见 v1.5 条目。

### 17.3 权限分级体系复杂，理解门槛高 ✅ 修复于 v0.11.0

- **现象**：原分级为 L0 直行 / L1 审批 / L2 强审 + 两段式 dry-run + 每会话限次，叠加 always_confirm 强审名单与会话级"L1 自动批准""L2 开关"两个开关，组合规则数量接近工具数的一半，且分散在审批卡、会话设置、文档多处表述。
- **影响**：管理员需要理解"哪些直接执行、哪些弹卡、哪些弹卡且不可豁免、哪些还要跑两次"的完整组合才能正确使用，理解门槛显著抬高；新增工具时的风险定级也是持续的心智负担。
- **修复**：会话行为收敛为审批三档位（需要审批 / 部分审批 / 完全权限），L2 每会话 5 次上限保留；旧开关取消、旧列兼容。
