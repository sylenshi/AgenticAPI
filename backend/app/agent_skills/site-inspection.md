# 站点巡检 SOP

## 执行步骤

1. **渠道连通性**：对每个启用渠道做单模型抽查（`test_channel` scope=one）。发现失败渠道时记录，暂不深挖。
2. **模型可用性**：执行 `generate_health_report`（含渠道抽查 + 模型快探 + 额度 + 存储），或分步执行 `test_all_models` 获取全量明细。
3. **额度水位**：`get_upstream_usage` scope=all 读取各上游 5h/周/月窗口。
4. **凭证有效期**：`get_token_expiry`，关注 daysLeft ≤ 7 的凭证。
5. **存储水位**：`get_chat_record_stats` + `get_log_stats`，行数超 10 万或占用超 50MB 给出治理建议。

## 报告模板（严格遵守）

```
# 站点巡检报告（YYYY-MM-DD HH:mm）

## 总览
- 健康度评分：X/100
- 结论一句话

## 渠道健康（N 个启用）
| 渠道 | 抽查模型 | 结果 | 时延 |
（失败渠道标红说明）

## 模型可用性
- 可用 X/N（可用率 XX%），平均时延 Xms
- 失败清单及原因分类（连通性/凭证/额度/映射）

## 额度水位
| 上游 | 5小时窗口 | 周窗口 | 月窗口 |
（≥80% 橙色预警，≥95% 红色预警）

## 凭证
（临期凭证单独列出，≤7 天）

## 存储水位
- chat_record / logs 行数与占用

## 待办建议
1. （可执行的下一步，标注风险等级）
```

## 判据

- 可用率 ≥ 95% 且无红色水位 → 评分 ≥ 90；
- 任一渠道全模型失败 → 扣 20 分并在待办置顶；
- 额度任一窗口 ≥ 95% → 红色预警，建议限制调用或补充额度。
