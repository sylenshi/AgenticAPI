# 故障复盘 SOP

## 执行步骤

1. **时间范围锁定**：与管理员确认故障起止时间（精确到分钟级）。
2. **证据收集**：
   - `get_usage_trend`（故障窗口，hour 粒度）看调用量/成功率形态；
   - 引导管理员在监控页按时间范围检索 logs（Agent 侧可用 `export_logs` 导出窗口内日志做离线分析）；
   - 若与上游相关：`get_upstream_usage` 看窗口水位是否打满。
3. **时间线还原**：把关键事件按时间排序（首次异常、扩散、峰值、恢复）。
4. **根因假设**：区分四类——上游侧（宕机/限流/凭证过期）、配置侧（渠道/映射/定价变更）、容量侧（额度耗尽/数据库膨胀）、调用侧（异常流量/重试风暴）。每类给支持与反对证据。
5. **改进项清单**：每项标注责任界面（管理页操作/Agent 可代办）与优先级。

## 报告模板

```
# 故障复盘（时间范围）
## 时间线
## 影响面（调用量/模型/用户数）
## 根因分析（主因 + 证据链）
## 改进项
1. …（优先级/责任界面/验收标准）
```

## 判据

- 时间线上异常先于配置变更 → 倾向上游侧；
- 窗口内额度 5h 桶打满且错误集中在 429 → 容量侧；
- 改进项必须可执行可验收，不写"加强监控"类空话。
